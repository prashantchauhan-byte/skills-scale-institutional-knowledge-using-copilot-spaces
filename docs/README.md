# OctoAcme Project Management Docs

## Overview

OctoAcme's project management approach is built on principles of customer-first delivery, iterative development, clear ownership, data-informed decisions, and psychological safety. These docs provide comprehensive guidance for all project team members—from initiation through retrospectives—to ensure consistent, repeatable project execution.

## Key Principles

- **Customer-first** — Prioritize customer value and usability in every decision
- **Iterative delivery** — Deliver small, testable increments to enable feedback and reduce risk
- **Clear ownership** — Each project has a named Project Manager (PM) and Product Lead
- **Data-informed decisions** — Measure impact, track metrics, and iterate based on evidence
- **Psychological safety** — Encourage feedback, learning, and blameless retrospectives

## Core Roles

| Role | Responsibility |
|------|-----------------|
| **Project Manager (PM)** | Coordinates delivery, manages schedules, risks, and communications |
| **Product Manager (PdM)** | Defines outcomes, prioritizes backlog, measures success, and gathers customer feedback |
| **Developers** | Implement features, collaborate on design, write tests, and maintain code quality |
| **QA/Testing** | Validates quality, verifies acceptance criteria, and conducts testing at all levels |
| **Stakeholders** | Provide business inputs, approvals, and executive alignment |

## Project Lifecycle

```
1. Initiation
   ↓
   Problem statement, stakeholders identified, high-level timeline sketched
   ↓
2. Planning
   ↓
   Scope defined, resources allocated, milestones and dependencies mapped
   ↓
3. Execution
   ↓
   Build, test, review, iterate—with daily standups and progress tracking
   ↓
4. Release
   ↓
   Deploy to production, run verification checks, communicate to stakeholders
   ↓
5. Close & Retrospective
   ↓
   Capture learnings and action items for future projects
```

## Key Artifacts

- **Project Charter / One-pager** — Business case, goals, success metrics, stakeholders
- **Roadmap and Release Plan** — Timeline, milestones, and key releases
- **Sprint/Iteration Backlog** — Prioritized list of work items with acceptance criteria
- **Risk Register** — Identified risks, impact, likelihood, and mitigation plans
- **Retrospective Notes** — Learnings, action items, and continuous improvement tracking

## Communication Cadence

- **Weekly PM + PdM Sync** — Strategic alignment and priority decisions
- **Twice-weekly Standups** — Delivery team progress, blockers, and dependencies
- **Monthly Stakeholder Updates** — High-level status, milestones, and risk communication
- **Ad-hoc Escalations** — Critical blockers or business-impacting issues

## Getting Started

**New Team Member?**
1. Start with [Project Management Overview](./octoacme-project-management-overview.md) for an introduction to our approach
2. Review the [Roles & Personas](./octoacme-roles-and-personas.md) document to understand team structure
3. Browse the core guides relevant to your role

**Starting a New Project?**
1. Follow the [Project Initiation](./octoacme-project-initiation.md) guide to validate and authorize the work
2. Use the [Project Planning](./octoacme-project-planning.md) guide to create your plan and backlog
3. Reference [Execution & Tracking](./octoacme-execution-and-tracking.md) during day-to-day delivery
4. Apply [Risk Management & Communication](./octoacme-risks-and-communication.md) throughout the project
5. Use the [Release & Deployment](./octoacme-release-and-deployment.md) guide when ready to ship
6. Close out with a [Retrospective & Continuous Improvement](./octoacme-retrospective-and-continuous-improvement.md) session

## How to Use These Docs
